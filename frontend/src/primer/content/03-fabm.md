# FABM 耦合框架

问题：一个在德国写的鱼类模块，怎样去“吃”一个在英国写的浮游动物模块里的变量，而且两边的代码一行都不用改？

宿主比较研究做的就是这件事：同一套 ECOSMO E2E 鱼类与底栖模块，分别接到 ECOSMO、ERSEM、ERGOM 三个低营养级模型上（Vijayakumaran et al. 2026）。耦合方式研究也用同样的办法，把 MIZER 鱼类粒径谱接到 ERSEM 上（Powley et al. 2026）。让这一切成为可能的是 FABM（Framework for Aquatic Biogeochemical Models，Bruggeman & Bolding, 2014）。

## 一个比喻：舞台、演员和接线板

- **宿主（host）**：物理模型，比如 GOTM 或 NEMO。它是舞台：管空间网格、水温和光照，负责让所有示踪物随水流和湍流移动，还负责往前推进时间。
- **模块（module / model）**：一段描述生物地球化学过程的代码，比如“浮游植物”“中型浮游动物”“鱼”。它是演员，只回答一个问题：*在这个格点、这一刻，我的变量每秒变多少？*
- **FABM**：接线板加剧本。有了它，宿主不用知道有哪些演员，演员也不用知道舞台是一维还是三维。

最重要的设计原则是：**模块里没有空间循环，也没有时间循环**。模块只写“局地的源汇项”，也就是这一点上的增加和减少。空间维度由宿主通过宏展开，时间积分也由宿主完成。

## 宿主做什么，模块做什么

对任何一个生物示踪物 $c_i$（比如硅藻碳），宿主要解的是：

$$
\frac{\partial c_i}{\partial t} = \underbrace{\frac{\partial}{\partial z}\left(\nu'_t \frac{\partial c_i}{\partial z}\right)}_{\text{湍流混合（宿主）}} - \underbrace{\frac{\partial (w_i c_i)}{\partial z}}_{\text{沉降/上浮}} + \underbrace{\sum_{m} S_i^{(m)}(\mathbf{c}, T, I, \dots)}_{\text{所有模块的源汇（FABM）}}
$$

- 第一项由 GOTM 算，用的就是[上一章](chapter:02-water-column)的湍流扩散率 $\nu'_t$；
- 沉降速度 $w_i$ 由模块告诉 FABM，再由宿主做垂直输送（GOTM 默认用带限制器的三阶迎风格式）；
- 最后一项是所有模块对 $c_i$ 的贡献加起来。比如硅藻碳会同时被“硅藻模块”（光合作用、呼吸）、“中型浮游动物模块”（摄食）和“鱼 1 模块”（如果鱼吃硅藻）改动。

GOTM 里源汇项用什么方法做时间积分，可以在 `gotm.yaml` 的 `fabm` 段选择：前向欧拉、二阶/四阶龙格–库塔，或者保证浓度不出现负值的 Patankar 类格式，还可以设置子步数。

> **想一想**：为什么由宿主而不是模块来做时间积分？
>
> 答：同一个时间步里，一个变量可能同时被好几个模块改动。如果每个模块各自往前推时间，就会遇到“先吃后长”还是“先长后吃”的顺序问题，质量也难守恒。宿主把所有模块的速率收齐后统一积分，所有过程都在同一时刻、用同一个状态计算。

## 变量的几种身份

模块初始化时，要向 FABM“登记”自己的变量。常见的身份有这几种：

| 身份 | 含义 | 例子 |
|---|---|---|
| 状态变量（state variable） | 有自己的方程、需要积分的量 | ERSEM 的 `P1/c`（硅藻碳）；E2E 的 `F1/c`（鱼 1 碳） |
| 水体内 vs 水平（底部/表面） | 水体内变量每层一个值，单位 m⁻³；水平变量每根水柱一个值，单位 m⁻² | 浮游生物和 E2E 的鱼是水体内变量；E2E 大型底栖、ERSEM 沉积物 `Q6` 是水平变量 |
| 诊断量（diagnostic） | 算出来供输出，不积分 | E2E 鱼的 `Fishint`（深度积分生物量）、`F1prey1`（对第 1 种饵料的摄食） |
| 依赖（dependency） | 模块要读、但不归它算的量 | 水温、光照、水深等“标准变量” |
| 状态依赖（state dependency） | 别的模块的状态变量；本模块可以读，**也可以给它加源汇项** | 鱼的 `prey1_c` 连到浮游动物 `Z4/c` |
| 聚合量（aggregate） | 把各模块的贡献加起来 | 总碳、总氮、总磷 |

双向耦合靠的就是“状态依赖”：鱼模块不只读 `Z4/c`，还往 `Z4/c` 上写一个负的源汇项。

E2E 的鱼类是个好例子。鱼的生物量登记成水平变量（mg C m⁻²），因为模型假设鱼能利用整根水柱的食物。鱼模块借助 FABM 内置的“垂直积分”子模块，先算出猎物在整根水柱里的总量

$$
P_X = \int_{\text{bottom}}^{\text{surface}} C_X\, dz
$$

用它算摄食，再按每层猎物占的比例 $C_X/P_X$，把摄食量分回各层（详见[功能群一章](chapter:07-functional-groups)）。MIZER 也是按深度积分的二维模型，同样按猎物的垂直分布把捕食分回各层。

## 按名字耦合：fabm.yaml

FABM 的配置写在一个人能看懂的 YAML 文件里。每个实例（instance）是某个模块的一份拷贝，有自己的名字、参数、初值和接线关系。同一个模块可以用好几次：ERSEM 的四种浮游植物 P1–P4 都是 `ersem/primary_producer` 模块，只是参数不同；E2E 的鱼 1 和鱼 2 都是 `e2e/fish` 模块。

下面是软件为 ERSEM 宿主生成的鱼 1（吃浮游动物的鱼）配置，有删节：

```yaml
instances:
  F1:
    long_name: planktivorous fish
    model: ecosmoe2e_fish        # 用哪个模块（官方 ECOSMO E2E 的鱼）
    parameters:
      mF1: 0.001                 # 死亡率 (d-1)
      excF1: 0.001               # 排泄率，0 °C 时 (d-1)
      tempcF1: 0.5               # 排泄的温度敏感性 θ (eV)
      asefF1: 0.7                # 同化效率
      rF1: 0.7                   # 半饱和常数 (mmol N m-2，代码内乘 79.6 换成 mg C)
      frr: 0.4                   # 未同化与死亡物质中进入 DOM 的比例
      GrF1Det: 0.0001            # 对碎屑的摄食率 (d-1)，碎屑和大型底栖是固定的两项
      GrF1MB1: 0.005             # 对大型底栖的摄食率 (d-1)
      nprey: 2                   # 另外 2 种浮游猎物
      Gr1: 0.033                 # 对猎物 1 的摄食率 (d-1)
      pref1: 0.4                 # 对猎物 1 的偏好
      compositionprey1: cnp      # 猎物 1（Z5）有碳、氮、磷三个变量
      Gr2: 0.033
      pref2: 0.4                 # 猎物 2（Z4）只有碳：氮、磷按 Redfield 比例隐含其中
      compositiondet: cnps       # 碎屑有碳、氮、磷、硅
      compositiondom: cnp
      scalenh4: 79.57            # 宿主 1 mmol N = 79.57 mg C
      scalepho: 1273.0           # 宿主 1 mmol P = 1273 mg C
      fix_dom: true              # 修正版的开关（见第 7 章）
    coupling:
      prey1: Z5/c                # 微型浮游动物
      preyn1: Z5/n
      preyp1: Z5/p
      prey2: Z4/c                # 中型浮游动物
      det: R6/c                  # 未同化和死亡物质 -> 中等粒级颗粒有机物
      detn: R6/n
      detp: R6/p
      dom: R1/c                  # -> 活性溶解有机物
      mb: MB/c                   # 另一个实例：大型底栖
      nh4: N4/n                  # 排泄 -> 铵盐
      pho: N1/p                  # 排泄 -> 磷酸盐
      oxy: O2/o                  # 氧
      dic: O3/c                  # 修正版：呼吸 -> 溶解无机碳
    initialization:
      c: 5.0                     # 初始浓度 (mg C m-3，鱼在每层都有值)
```

（这是软件为 ERSEM 宿主生成的鱼 1，略去了几行同类项。）

读这份文件时注意三点：

1. **`coupling` 下面写的全是名字。** `prey2: Z4/c` 的意思是：把我登记的状态依赖 `prey2`，接到实例 `Z4` 的变量 `c` 上。FABM 初始化时按名字查找，把线接好。
2. 鱼的“菜单”长度可变。`nprey` 和 `GrN`、`prefN`、`preyN` 组成一个数组，猎物可以随意加减，鱼 2 还可以把 `F1/c` 当猎物。
3. 组分字符串决定哪些元素要守恒。模块靠检查这个字符串来决定是否追踪氮、磷、硅：组分里有 `n`，被吃掉的氮就要从猎物里扣掉，并回到宿主的氮库。官方代码扣氮、扣磷都按 Redfield 比例（鱼体只记碳，氮磷按固定比例隐含），不按猎物实际的氮碳比。

换成 ECOSMO 宿主，同一条鱼 1 只要把 `coupling` 改成 `prey1: ECO/microzoo`、`prey2: ECO/mesozoo`、`det: ECO/det` 等，模块代码一个字都不用动。

## 为什么不用重新编译

增加鱼类群、改变食性和速率，都不需要重新编译。原因有两条：

- 软件的 `kernel/build.py` 已经把 ERSEM、MIZER、E2E 三个模块库，连同 FABM 自带的 ECOSMO、ERGOM，一起编进了同一个 `gotm` 可执行文件。所有“演员”都已经在后台候场。
- `fabm.yaml` 要到**运行开始时**才读：用哪些实例、实例之间怎么接线、参数取多少，都是运行时才定的。

只有写一个全新的模块（新的方程）时，才需要重新编译。所以软件的[食物网页](app:foodweb)可以在网页上随意组合宿主和高营养级：后端做的只是拼一份新的 `fabm.yaml`。

## 质量守恒

双向耦合有一条硬规矩：**每一笔通量都要在两个账户上同时记账**，一边减多少，另一边就加多少。所有通量都通过共享的数据结构处理，所以质量守恒。

以鱼 1 吃掉 1 mg C 浮游动物为例（同化效率 $\gamma_{F1}=0.7$；没被同化的部分里进入溶解有机物的比例 $f_{rr}$ 取官方算例的 0.4）：

| 账户 | 变化 |
|---|---|
| 浮游动物 | $-1$ |
| 鱼 1 | $+\gamma = +0.7$ |
| 碎屑 | $+(1-f_{rr})(1-\gamma) = +0.18$ |
| 溶解有机物 | $+f_{rr}(1-\gamma) = +0.12$ |
| 合计 | $0$ |

（鱼的排泄和死亡另有去处，同样两边记账：排泄的碳以 CO₂ 形式进入溶解无机碳 DIC，氮和磷进入铵盐和磷酸盐，同时消耗氧。）写成一般形式，对任何守恒元素：

$$
\frac{d}{dt}\left(\sum_{\text{所有库}} c_j\right) = \text{边界通量（海–气、沉积埋藏、松弛等）}
$$

为了能检查这一点，模块可以把自己的变量登记进“总碳”“总氮”“总磷”等聚合量。ERSEM 和 FABM-MIZER 都这样做；官方 E2E 代码没有登记，鱼和大型底栖动物的碳、氮、磷要自己按 1/12.01、Redfield 比例换算后加进去。

要注意，“共享数据结构所以守恒”只是说框架允许两边同时记账，每一笔是否真的记对，还要看模块代码本身。官方 E2E 代码就有几处没记对：上表里溶解有机物那 0.12，在原样代码里并没有加到任何变量上；呼吸的碳不进入 DIC，鱼呼吸反而增加氧气。本软件的修正版改正了这些（[第 7 章](chapter:07-functional-groups)）。

## 单位与换算因子

不同宿主用的“货币”不一样，这是耦合时最容易出错的地方：

| 宿主 | 生物量单位 | 营养盐单位 |
|---|---|---|
| ERSEM | mg C m⁻³ | mmol N/P/Si m⁻³；DIC（O3/c）为 mmol C m⁻³ |
| ECOSMO | mg C m⁻³ | 也以碳当量 mg C m⁻³ 表示（按 Redfield 比换算） |
| ERGOM | mmol N m⁻³ | mmol N m⁻³ 与 mmol P m⁻³ |

E2E 内部用 mg C 计。官方代码给每个连接设一个换算系数 `scale…`，含义是“宿主的 1 个单位等于多少 mg C”：读入时乘它，写回宿主时除以它。软件会自动算好：

- **ERSEM 的铵盐和磷酸盐**：Redfield 比（海洋浮游生物典型的元素比例）C:N $=106:16=6.625$（摩尔比），所以 $1\ \mathrm{mmol\,N}$ 相当于 $6.625\times12.01\approx79.6\ \mathrm{mg\,C}$，`scalenh4` $=79.57$；磷酸盐 $1\ \mathrm{mmol\,P}\leftrightarrow106\times12.01\approx1273\ \mathrm{mg\,C}$，`scalepho` $=1273$。
- **ERSEM 的 DIC**（修正版用到）：$1\ \mathrm{mmol\,C} = 12.01\ \mathrm{mg\,C}$，`scaledic` $=12.01$。
- **ECOSMO**：营养盐本来就以碳当量 mg C 计，不需要换算。
- **ERGOM**：浮游生物、碎屑都以 mmol N 计，`scaleprey`、`scaledet` 等取 79.6；营养盐以 mmol N、mmol P 计，`scalenh4` $=79.57$、`scalepho` $=1273$。

举个例子：如果宿主的碎屑以 mol C kg⁻¹ 计，而 E2E 要的是 mg C m⁻³，乘子约为

$$
1\ \mathrm{mol\,C\,kg^{-1}} \times 12011\ \mathrm{mg\,mol^{-1}} \times 1025\ \mathrm{kg\,m^{-3}} \approx 1.23\times10^{7}\ \mathrm{mg\,C\,m^{-3}}
$$

> **想一想**：ERSEM 的中型浮游动物 Z4 只有一个碳变量，为什么也能参与氮、磷的守恒？
>
> 答：ERSEM 假定 Z4 的元素比例固定：$q_N = 0.0126\ \mathrm{mmol\,N\,(mg\,C)^{-1}}$，$q_P = 0.000786\ \mathrm{mmol\,P\,(mg\,C)^{-1}}$。换成摩尔比，C:N $= (1/12.011)/0.0126 \approx 6.6$，C:P $\approx 106$，正好是 Redfield 比。鱼吃掉 Z4 的碳时，氮和磷就按这两个比例一起算。

## 容易误解的地方

- **FABM 不是生态模型。** 它自己没有任何方程，只负责登记、接线和传递速率。只说“用 FABM 跑的结果”是不完整的，要说清用了哪些模块。
- **FABM 按名字接线，但不管生态上合不合理。** 你完全可以让鱼去“吃”硝酸盐，FABM 不会报错。食性是否合理，要使用者自己把关。
- **单位错了也不会报错。** 换算因子写错，模型照样能跑，只是结果差了几十倍。比较不同宿主之前，先确认单位。
- **FABM 里也能做“单向耦合”。** 耦合方式研究的离线模拟是单独跑 MIZER，用事先存下的基线 ERSEM 输出来驱动（Powley et al. 2026）。软件用的是一个思路相同、但更省事的做法：FABM-MIZER 模块有个 `feedback` 参数（默认开启），关掉后鱼照常读取猎物，但不把捕食、排泄、呼吸等通量写回宿主。软件里的“单向耦合”配置就是 `feedback: false`。
- **改 `fabm.yaml` 不用重新编译，改模块源码才要。** 在网页上调参数属于前一种。
