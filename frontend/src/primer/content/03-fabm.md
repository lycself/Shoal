# 生态模块怎么接进物理模型：FABM

如果一个鱼类模块和一个浮游生物模型由不同团队分别开发，能不能在不修改两边源代码的前提下，让鱼类直接捕食那个模型里的浮游动物？

在 Shoal 中，同一套高营养级鱼类与底栖动物模块可以分别耦合到 ERSEM、ECOSMO 和 ERGOM 三个低营养级模型上（Vijayakumaran 等 2026）；粒径谱鱼类模块 MIZER 也通过同样的方式耦合到 ERSEM 上（Powley 等 2026）。支撑这种跨模块组合的耦合框架是 **FABM**（Framework for Aquatic Biogeochemical Models，水生生物地球化学模型框架；Bruggeman 和 Bolding 2014）。

## 物理模型、生态模块与 FABM 的分工

在 GOTM–FABM 体系中，物理模型、生态模块和耦合框架各自承担明确的职责：

- **物理模型**（如一维水柱模型 GOTM 或三维海洋模型 NEMO）：负责计算水温、盐度、光照衰减、湍流扩散与水体平流，对所有溶解或悬浮示踪物进行空间输运，并统一执行时间积分。
- **生态模块**（如硅藻、中型浮游动物、鱼类功能群）：只计算局部生物地球化学过程，即在给定空间位置和当前时刻，各个状态变量每秒增加或减少的速率（源汇项）。
- **FABM 框架**：负责变量注册、跨模块依赖解析与速率汇总。它在模型启动时读取配置文件，将各个生态模块的输入与输出按名称连接起来，并在每个时间步把汇总后的源汇项交给物理模型推进时间。

FABM 的核心设计原则是：**生态模块内部不包含空间循环，也不包含时间步进**。模块只编写局地源汇项，空间网格是一维水柱还是三维海洋、时间积分用什么数值格式，完全由外层物理模型决定。由于所有模块都在同一时刻基于同一状态计算变化率，再由物理模型统一推进，从而避免了“先算捕食还是先算生长”的顺序依赖，并保证了跨模块通量的质量守恒。

> **术语说明**：FABM 官方文档将外层物理模型（如 GOTM、NEMO）称为 host（宿主）。而在端到端生态建模文献及本软件中，**“宿主”专指提供低营养级环境的生态模型**（即 ERSEM、ECOSMO、ERGOM 三选一），GOTM 则统称为“物理模型”。

## 物理输运与局地源汇的合成

以水体中的硅藻浓度为例，某一深度层上的浓度变化由三部分合成：

1. **垂向湍流混合**：由物理模型根据湍流扩散率计算上下水层之间的交换（见[水柱物理一章](chapter:02-water-column)）。
2. **颗粒沉降**：沉降速率由硅藻模块提供给 FABM，实际的垂向平流输运由物理模型完成。
3. **生物地球化学源汇**：光合作用生长与呼吸消耗由硅藻模块计算，浮游动物摄食损失由浮游动物模块计算，若鱼类或底栖动物摄食硅藻，高营养级模块也会贡献一项负速率。FABM 将所有模块对该变量的源汇项相加后交给物理模型。

## 变量类型与注册机制

每个生态模块在初始化时向 FABM 注册其包含的变量及外部依赖：

| 变量类别 | 含义 | 示例 |
|---|---|---|
| 状态变量（state variable） | 由本模块定义、需要随时间积分演化的变量 | ERSEM 的 `P1/c`（硅藻碳）、E2E 的 `F1/c`（鱼 1 碳） |
| 水体变量与界面变量 | 水体变量（pelagic）每层网格一个值（每立方米）；底栖/水平界面变量（bottom/horizontal）整根水柱一个值（每平方米） | 浮游生物为水体变量；E2E 大型底栖动物 `MB/c`、ERSEM 沉积有机物 `Q6` 为底栖界面变量 |
| 诊断变量（diagnostic） | 仅用于输出诊断的中间计算量，不直接参与时间积分 | E2E 的 `F1_Fishint`（鱼 1 深度积分量）、`F1prey1`（对猎物 1 的摄食率） |
| 环境依赖（dependency） | 模块需要读取但不修改的环境场 | 水温、光合有效辐射、水深 |
| 状态依赖（state dependency） | 引用其他模块的状态变量，**既可读取浓度，也可向其累加源汇项** | 鱼类模块的 `prey1` 连接到浮游动物 `Z4/c` |
| 聚合变量（aggregate） | 自动汇总各模块贡献的守恒总量 | 总碳、总氮、总磷、总硅 |

双向耦合（鱼类摄食真正消耗猎物生物量，排泄物真正归还营养盐库）正是通过“状态依赖”实现的：鱼类模块不仅读取 `Z4/c` 的当前浓度，还直接向 `Z4/c` 累加负的捕食速率。

## fabm.yaml：按名称配置耦合关系

FABM 的模块组合与接线写在文本配置文件 `fabm.yaml` 中。文件中的每个“实例”（instance）对应某个模块的一份具体配置，拥有独立的名称、参数、初值和耦合目标。同一个底层模块可以实例化多次：例如 ERSEM 的四类浮游植物 P1–P4 共用同一个浮游植物模块，E2E 的鱼 1 和鱼 2 共用同一个鱼类模块。

下面是 Shoal 为 ERSEM 宿主生成的鱼 1（浮游食性鱼）配置节选：

```yaml
instances:
  F1:
    long_name: planktivorous fish
    model: ecosmoe2e_fish        # 调用的底层 Fortran 模块名
    parameters:
      mF1: 0.001                 # 死亡率 (d-1)
      excF1: 0.001               # 排泄率，0 °C 参考值 (d-1)
      tempcF1: 0.5               # 排泄温度敏感性参数 θ (eV)
      asefF1: 0.7                # 同化效率
      rF1: 0.7                   # 半饱和常数 (mmol N m-2，代码内乘 79.6 换算为 mg C)
      frr: 0.4                   # 未同化与死亡物质中进入 DOM 的比例
      GrF1Det: 0.0001            # 对碎屑的最大摄食率 (d-1)
      GrF1MB1: 0.005             # 对大型底栖动物的最大摄食率 (d-1)
      nprey: 2                   # 浮游猎物数量
      Gr1: 0.033                 # 对猎物 1 的最大摄食率 (d-1)
      pref1: 0.4                 # 对猎物 1 的摄食偏好
      compositionprey1: cnp      # 猎物 1（Z5）包含碳、氮、磷三个状态变量
      Gr2: 0.033
      pref2: 0.4                 # 猎物 2（Z4）仅有碳变量，氮、磷按固定 Redfield 比推算
      compositiondet: cnps       # 碎屑包含碳、氮、磷、硅
      compositiondom: cnp
      scalenh4: 79.57            # 宿主 1 mmol N = 79.57 mg C
      scalepho: 1273.0           # 宿主 1 mmol P = 1273 mg C
      fix_dom: true              # 启用物质收支修正版（见功能群一章）
    coupling:
      prey1: Z5/c                # 微型浮游动物
      preyn1: Z5/n
      preyp1: Z5/p
      prey2: Z4/c                # 中型浮游动物
      det: R6/c                  # 未同化和死亡颗粒物 -> 中粒级碎屑 R6
      detn: R6/n
      detp: R6/p
      dom: R1/c                  # 溶解排泄物 -> 活性溶解有机物 R1
      mb: MB/c                   # 大型底栖动物实例
      nh4: N4/n                  # 排泄铵氮 -> 铵盐 N4
      pho: N1/p                  # 排泄磷 -> 磷酸盐 N1
      oxy: O2/o                  # 溶解氧
      dic: O3/c                  # 呼吸碳 -> 溶解无机碳 O3
    initialization:
      c: 5.0                     # 初始浓度 (mg C m-3)
```

配置文件中每个实例包含四个字段：

- `model`：指定调用的 Fortran 模块名。
- `parameters`：模块参数，如最大摄食率、摄食偏好、半饱和常数和同化效率（参数定义详见[功能群一章](chapter:07-functional-groups)）。
- `coupling`：跨模块变量映射。左端为本模块内部声明的接口名，右端为宿主或其他模块中的目标变量名（如 `prey2: Z4/c` 将猎物 2 连接到实例 `Z4` 的碳变量 `c`）。
- `initialization`：状态变量的初始值。

其中 `compositionprey1: cnp` 等组分字符串用于指明目标猎物包含哪些显式元素变量。当组分包含 `n` 和 `p` 时，模块在扣除猎物碳的同时，也会从对应的氮、磷变量中扣除相应通量。如果将宿主从 ERSEM 切换为 ECOSMO，只需把 `coupling` 下的目标变量改为 `ECO/microzoo`、`ECO/mesozoo`、`ECO/det` 等，Fortran 模块代码无需任何改动。

## 为什么切换配置无需重新编译

在[食物网配置](app:foodweb)页切换宿主、增减鱼类功能群或修改参数时，软件不需要重新编译二进制程序，原因在于：

- Shoal 的计算内核 `gotm` 在构建时已将 ERSEM、FABM-MIZER、ECOSMO E2E 以及 FABM 内置的 ECOSMO、ERGOM 全部编译进了同一个可执行文件；
- `fabm.yaml` 在每次模拟启动时动态解析，启用哪些模块实例、如何连接变量、参数取何值均在运行时决定。

因此，前端界面的修改只需由后端重新生成一份 `fabm.yaml` 即可生效。只有修改模块内部的微分方程（Fortran 源码）时才需要重新编译内核。

## 质量守恒：双向记账

在双向耦合模型中，任何一笔跨模块物质转移都必须在源账户和汇账户上同时增减相同质量的物质。

以鱼 1 摄食 1 mg C 浮游动物为例，设同化效率为 0.7，未同化部分中 40% 进入溶解有机物（DOM）、60% 进入颗粒碎屑：

| 变量账户 | 变化量 (mg C) |
|---|---|
| 浮游动物 | −1.00 |
| 鱼 1 | +0.70 |
| 颗粒碎屑 | +0.18（0.3 × 0.6） |
| 溶解有机物 | +0.12（0.3 × 0.4） |
| **合计** | **0.00** |

同理，鱼类的呼吸与排泄在减少自身碳生物量的同时，将碳、氮、磷分别归还至溶解无机碳（DIC）、铵盐和磷酸盐，并按化学计量比消耗溶解氧。

需要注意的是，FABM 框架只提供跨模块读写接口，收支是否严格闭合取决于模块代码本身的实现。例如官方 E2E 原始代码中遗漏了水层鱼类排入 DOM 的通量（上表中的 +0.12 mg C），且呼吸碳未进入 DIC、耗氧方向写反；Shoal 的物质收支修正版修复了这些漏项（详见[功能群一章](chapter:07-functional-groups)）。

## 单位与化学计量换算

三个低营养级宿主采用不同的内部记账单位，跨模块连接时必须进行单位换算：

| 宿主 | 浮游生物与碎屑单位 | 营养盐单位 |
|---|---|---|
| ERSEM | mg C m⁻³ | mmol N/P/Si m⁻³；DIC 为 mmol C m⁻³ |
| ECOSMO | mg C m⁻³ | 按 Redfield 比折算为碳当量 mg C m⁻³ |
| ERGOM | mmol N m⁻³ | mmol N m⁻³、mmol P m⁻³ |

E2E 鱼类模块内部统一以 mg C 记账，不同元素之间按照经典的 **Redfield 摩尔比**（C:N:P = 106:16:1；Redfield 1934）换算：1 mmol N 对应 $106/16 = 6.625$ mmol C，乘以碳摩尔质量 $12.011\ \mathrm{g\,mol^{-1}}$ 得约 $79.57\ \mathrm{mg\,C}$；1 mmol P 对应 $106 \times 12.011 \approx 1273\ \mathrm{mg\,C}$。

E2E 模块通过 `scaleprey`、`scalenh4`、`scalepho` 等缩放系数完成单位对齐（表示宿主 1 单位相当于多少 mg C，读取时相乘、写回时相除）。FABM 本身不会自动检查两边物理量纲是否匹配——如果缩放系数填错，程序仍会正常运行，但通量大小会相差数十倍。Shoal 会根据所选宿主自动填入对应的换算系数。

对于像 ERSEM 中型浮游动物 Z4 这样只设单一碳变量（`Z4/c`）但具有固定化学计量比的类群（每 mg C 固定含 0.0126 mmol N 和 0.000786 mmol P，即 Redfield 比），鱼类摄食 `Z4/c` 时按相同比例同步核算氮、磷通量，从而保证总氮与总磷守恒。

## 深入一点：输运–反应方程与积分格式

**一维示踪物方程。** 对于水体中的任意状态变量 $c_i$，GOTM–FABM 求解如下偏微分方程：

$$
\frac{\partial c_i}{\partial t} = \underbrace{\frac{\partial}{\partial z}\left(\nu'_t \frac{\partial c_i}{\partial z}\right)}_{\text{垂向湍流混合（GOTM）}} - \underbrace{\frac{\partial (w_i c_i)}{\partial z}}_{\text{沉降/上浮（GOTM）}} + \underbrace{\sum_{m} S_i^{(m)}(\mathbf{c}, T, I, \dots)}_{\text{生态模块源汇项之和（FABM）}}
$$

其中 $\nu'_t$ 为湍流扩散率，$w_i$ 为模块注册的垂向迁移或沉降速度（向下为负），$S_i^{(m)}$ 为第 $m$ 个生态模块对变量 $c_i$ 的源汇贡献。GOTM 对垂向沉降平流默认采用带通量限制器的三阶迎风格式（TVD）。

**深度积分摄食与垂向分配。** E2E 鱼类和 MIZER 粒径谱均基于整根水柱的猎物深度积分总量计算摄食：

$$
P_X = \int_{\text{bottom}}^{\text{surface}} C_X(z)\, dz
$$

其中 $C_X(z)$ 为猎物 $X$ 在各层的浓度（mg C m⁻³），$P_X$ 为水柱积分生物量（mg C m⁻²）。算出总摄食量后，E2E 按各层猎物占比 $C_X(z)/P_X$ 将捕食损失分配回各个深度层；MIZER 则按所有浮游猎物总生物量的垂向分布比例分配捕食与排泄通量（见[粒径谱一章](chapter:06-size-spectrum)）。

**守恒律。** 对任意守恒元素（如碳、氮、磷、硅），对水柱各层及底栖库求和后满足：

$$
\frac{d}{dt}\left(\sum_{\text{所有库}} c_j\right) = \text{边界通量}
$$

右端边界通量仅包含海–气气体交换、海底永久埋藏、渔获上岸移除以及向气候态剖面的松弛项。

## 几点注意

- **FABM 是耦合框架而非具体生态模型。** 报告模拟方法时应指明所用的具体生态模块（如 ERSEM + MIZER 或 ECOSMO + E2E），而不只是“使用 FABM 模型”。
- **FABM 只检查变量名是否存在，不检查生态学合理性或量纲一致性。** 手动编辑配置时需自行核对猎物类型与单位换算系数。
- **单向耦合也可以在 FABM 在线运行中实现。** FABM-MIZER 提供布尔参数 `feedback`（默认 `true`）；设为 `false` 时，鱼类模块照常读取 ERSEM 猎物浓度并计算生长，但不向 ERSEM 写回捕食、排泄和呼吸通量，效果等价于用无鱼基线离线驱动鱼类模型（见[单向与双向耦合一章](chapter:08-coupling)）。
