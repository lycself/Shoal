# 生态模块怎么接进物理模型：FABM

> **一句话**：FABM 是一块“接线板”，让不同人写的生态模块（浮游生物、鱼、底栖动物）在运行时按名字接到一起，再一起放进物理模型里计算。

**这一章你会明白**

- 物理模型、生态模块和 FABM 三者各负责什么；
- 一个鱼类模块怎样“吃”另一个模型里的浮游动物，而两边代码都不用改；
- `fabm.yaml` 配置文件怎么读；
- 为什么在网页上换宿主、加减鱼类不需要重新编译；
- 双向耦合时物质怎样守恒，不同模型的单位怎样换算。

## 一个插头和插座的问题

设想这样一件事：一个鱼类模块是德国的研究组写的，一个浮游动物模型是英国的研究组写的。现在想让这条“鱼”去吃那个模型里的浮游动物，而且两边的代码一行都不改。这能做到吗？

能。本软件里，同一套鱼类与底栖动物模块可以分别接到 ERSEM、ECOSMO、ERGOM 三个低营养级模型上（方法参考：Vijayakumaran 等 2026）；粒径谱鱼类模块 MIZER 也是用同样的办法接到 ERSEM 上（方法参考：Powley 等 2026）。这里的低营养级，指食物链下半段：营养盐、浮游植物、浮游动物、细菌和碎屑（死掉的有机颗粒）。

让这件事成为可能的工具叫 FABM（Framework for Aquatic Biogeochemical Models，水生生物地球化学模型框架；Bruggeman 和 Bolding 2014）。它像墙上的标准插座：只要电器（生态模块）按标准做插头，就能插在任何一面墙（物理模型）上。

## 舞台、演员和接线板

- **物理模型**：比如本软件用的一维水柱模型 GOTM，或三维海洋模型 NEMO。它是舞台，管水深、分层、水温、光照和湍流（水里大大小小的涡旋），负责让所有溶解或悬浮在水里的物质随湍流上下搬运，并一步步往前推进时间。
- **生态模块**：一段描述生物或化学过程的代码，比如“硅藻”“中型浮游动物”“鱼 1”。它是演员，只回答一个问题：在这个位置、这一刻，我管的量每秒增加或减少多少？
- **FABM**：接线板加剧本。它记下每个演员有哪些变量、要读哪些量，按配置文件把它们连起来，再把所有速率交给舞台。有了它，舞台不用知道有哪些演员，演员也不用知道舞台是一维还是三维。

最重要的设计原则是：**生态模块里没有空间循环，也没有时间循环**。模块只写“这一点上的增加和减少”（叫源汇项：源是增加，汇是减少）。在哪些格点上算、怎样往前推进时间，都由物理模型负责。

> **关于“宿主”这个词**：FABM 的官方文档把物理模型（GOTM、NEMO）叫作 host（宿主）。本软件和本教程不这样用。在这里，**宿主专指负责低营养级的生态模型**，也就是 ERSEM、ECOSMO、ERGOM 三选一，鱼类模块“寄住”在它上面取食。GOTM 在本教程里一律叫“物理模型”。

## 物理模型做什么，模块做什么

以硅藻为例，它在某一层的浓度会因为三件事变化：

1. 湍流把它和上下层的水混在一起。这由物理模型算，用的是[水柱物理一章](chapter:02-water-column)里的湍流扩散率。
2. 它会慢慢下沉。下沉有多快由硅藻模块告诉 FABM，实际的上下搬运由物理模型完成。
3. 生物过程让它增减：光合作用让它变多，呼吸和被吃让它变少。这些分别来自不同的模块：硅藻模块管生长和呼吸，浮游动物模块管摄食，如果鱼吃硅藻，鱼的模块也会贡献一项。

FABM 把第 3 项里所有模块的贡献加起来，交给物理模型，由物理模型统一往前推进一步。

> **想一想**：为什么由物理模型而不是各个模块来推进时间？
>
> 答：同一时刻，一个量可能同时被好几个模块改动。如果每个模块各自往前推，就会出现“先吃后长”还是“先长后吃”的顺序问题，物质也难以守恒。把所有速率收齐后统一推进，所有过程就都在同一时刻、用同一个状态计算。

## 变量的几种身份

每个模块启动时，要向 FABM“登记”自己的变量。可以把它想成入职登记：哪些东西归你管，哪些东西你要借用。

| 身份 | 大白话 | 例子 |
|---|---|---|
| 状态变量 | 归这个模块管、要一步步算下去的量 | ERSEM 的 `P1/c`（硅藻碳）；E2E 的 `F1/c`（鱼 1 的碳） |
| 水体变量和水平变量 | 水体变量每一层一个值（每立方米多少）；水平变量整根水柱只有一个值（每平方米多少），比如海底的沉积物 | 浮游生物是水体变量；E2E 的大型底栖动物、ERSEM 的沉积有机物 `Q6` 是水平变量 |
| 诊断量 | 只为输出看结果而算，不往下积累 | E2E 的 `F1_Fishint`（鱼 1 的深度积分量）、`F1prey1`（鱼 1 对第 1 种猎物的摄食） |
| 依赖 | 模块要读、但不归它算的环境量 | 水温、光照、水深 |
| 状态依赖 | 别的模块的状态变量。本模块可以读，**也可以往上面加减** | 鱼的 `prey1_c` 接到浮游动物 `Z4/c` 上 |
| 聚合量 | 把各模块的贡献加起来的总数 | 总碳、总氮、总磷 |

双向耦合（鱼吃掉的东西真的从猎物里扣掉）靠的就是“状态依赖”：鱼模块不只读 `Z4/c`，还往 `Z4/c` 上写一个负的变化率。

## fabm.yaml：按名字接线

FABM 的配置写在一个叫 `fabm.yaml` 的文本文件里，人能直接读懂。文件里每一个“实例”是某个模块的一份拷贝，有自己的名字、参数、初值和接线。同一个模块可以用好几次：ERSEM 的四类浮游植物 P1–P4 都是同一个“浮游植物”模块，只是参数不同；E2E 的鱼 1 和鱼 2 也都是同一个“鱼”模块。

下面是软件为 ERSEM 宿主生成的鱼 1（主要吃浮游动物的鱼）配置，略去了几行同类项：

```yaml
instances:
  F1:
    long_name: planktivorous fish
    model: ecosmoe2e_fish        # 用哪个模块（官方 ECOSMO E2E 的鱼）
    parameters:
      mF1: 0.001                 # 死亡率 (d-1)
      excF1: 0.001               # 排泄率，0 °C 时 (d-1)
      tempcF1: 0.5               # 排泄的温度敏感性 θ (eV)
      asefF1: 0.7                # 同化效率
      rF1: 0.7                   # 半饱和常数 (mmol N m-2，代码内乘 79.6 换成 mg C)
      frr: 0.4                   # 未同化与死亡物质中进入 DOM 的比例
      GrF1Det: 0.0001            # 对碎屑的摄食率 (d-1)，碎屑和大型底栖是固定的两项
      GrF1MB1: 0.005             # 对大型底栖的摄食率 (d-1)
      nprey: 2                   # 另外 2 种浮游猎物
      Gr1: 0.033                 # 对猎物 1 的摄食率 (d-1)
      pref1: 0.4                 # 对猎物 1 的偏好
      compositionprey1: cnp      # 猎物 1（Z5）有碳、氮、磷三个变量
      Gr2: 0.033
      pref2: 0.4                 # 猎物 2（Z4）只有碳：氮、磷按 Redfield 比例隐含其中
      compositiondet: cnps       # 碎屑有碳、氮、磷、硅
      compositiondom: cnp
      scalenh4: 79.57            # 宿主 1 mmol N = 79.57 mg C
      scalepho: 1273.0           # 宿主 1 mmol P = 1273 mg C
      fix_dom: true              # 修正版的开关（见功能群一章）
    coupling:
      prey1: Z5/c                # 微型浮游动物
      preyn1: Z5/n
      preyp1: Z5/p
      prey2: Z4/c                # 中型浮游动物
      det: R6/c                  # 未同化和死亡物质 -> 中等粒级颗粒有机物
      detn: R6/n
      detp: R6/p
      dom: R1/c                  # -> 活性溶解有机物
      mb: MB/c                   # 另一个实例：大型底栖
      nh4: N4/n                  # 排泄 -> 铵盐
      pho: N1/p                  # 排泄 -> 磷酸盐
      oxy: O2/o                  # 氧
      dic: O3/c                  # 修正版：呼吸 -> 溶解无机碳
    initialization:
      c: 5.0                     # 初始浓度 (mg C m-3，鱼在每层都有值)
```

文件分四块：

- `model`：这个实例用哪个模块的代码。
- `parameters`：参数。摄食率是“每单位鱼每天最多吃掉多少”，偏好是几种猎物摆在面前时更爱吃哪种的权重（0–1），半饱和常数是“食物多到多少，摄食才达到最大值的一半”，同化效率是吃下去的食物里真正吸收进身体的比例。这些词在[功能群一章](chapter:07-functional-groups)里还会细讲。
- `coupling`：接线。左边是鱼模块登记的“插口”名字，右边是要接到的变量。`prey2: Z4/c` 的意思是：把我的插口 `prey2` 接到实例 `Z4` 的变量 `c`（中型浮游动物的碳）上。
- `initialization`：初始值。

读这份文件时留意三点：

1. **`coupling` 下面写的全是名字。** FABM 启动时按名字查找，把线接好。
2. **鱼的“菜单”长度可变。** `nprey` 和 `GrN`、`prefN`、`preyN` 组成一组，猎物可以随意加减；鱼 2 还可以把 `F1/c`（鱼 1）当猎物。
3. **组分字符串决定哪些元素要守恒。** `cnp` 表示这个猎物有碳、氮、磷三个变量。组分里有 `n`，被吃掉的氮就要从猎物里扣掉，并还给宿主的氮库。

换成 ECOSMO 宿主时，同一条鱼 1 只要把 `coupling` 改成 `prey1: ECO/microzoo`、`prey2: ECO/mesozoo`、`det: ECO/det` 等，模块代码一个字都不用动。

## 为什么不用重新编译

在[食物网配置](app:foodweb)页换宿主、加减鱼类、改食性和参数，都不需要重新编译程序。原因有两条：

- 软件的计算内核已经把 ERSEM、MIZER、E2E 三个模块库，连同 FABM 自带的 ECOSMO、ERGOM，一起编进了同一个 `gotm` 程序。所有“演员”都已经在后台候场。
- `fabm.yaml` 要到**每次运行开始时**才读。用哪些实例、怎么接线、参数取多少，都是运行时才定的。

所以网页上的每一次修改，后端做的只是重新拼一份 `fabm.yaml`。只有写一个全新的模块（新的方程）时，才需要重新编译。

## 物质守恒：每笔账记两边

双向耦合有一条硬规矩：**每一笔物质流动都要在两个账户上同时记账**，一边减多少，另一边就加多少，像银行转账。

以鱼 1 吃掉 1 mg 碳的浮游动物为例。设同化效率为 0.7，没吸收的部分里有 40% 变成溶解有机物（DOM，溶在水里的有机分子），其余 60% 变成碎屑：

| 账户 | 变化 (mg C) |
|---|---|
| 浮游动物 | −1 |
| 鱼 1 | +0.7 |
| 碎屑 | +0.18（0.3 × 0.6） |
| 溶解有机物 | +0.12（0.3 × 0.4） |
| 合计 | 0 |

鱼的排泄和死亡也同样记两边：排泄的碳以二氧化碳形式进入溶解无机碳（DIC），氮和磷进入铵盐和磷酸盐，同时消耗氧气。

不过要注意，FABM 只是**允许**两边同时记账，每一笔记得对不对，要看模块代码本身。官方 E2E 代码就有几处没记对：上表里溶解有机物那 0.12，原样代码并没有加到任何变量上；呼吸的碳不进入 DIC，鱼呼吸反而让氧气增加。本软件的修正版改正了这些（见[功能群一章](chapter:07-functional-groups)的“本软件如何实现”）。

## 单位：不同模型用不同的“货币”

三个宿主记账用的单位不一样，这是接线时最容易出错的地方：

| 宿主 | 生物量单位 | 营养盐单位 |
|---|---|---|
| ERSEM | mg C m⁻³（每立方米多少毫克碳） | mmol N/P/Si m⁻³；DIC 为 mmol C m⁻³ |
| ECOSMO | mg C m⁻³ | 也折算成碳，mg C m⁻³ |
| ERGOM | mmol N m⁻³（每立方米多少毫摩尔氮） | mmol N m⁻³ 和 mmol P m⁻³ |

E2E 鱼类模块内部用毫克碳记账。不同元素之间怎么换算？靠 **Redfield 比**：海洋浮游生物体内碳、氮、磷的原子数之比大致固定在 106:16:1（Redfield 1934 年总结的经验比例）。所以 1 mmol 氮大约对应 6.625 mmol 碳，也就是约 79.6 mg 碳。

官方代码给每根线设一个换算系数 `scale…`，意思是“宿主的 1 个单位等于多少 mg C”：读进来时乘它，写回宿主时除以它。软件会自动填好这些系数。

> **想一想**：单位换算系数写错了，模型会报错吗？
>
> 答：不会。模型照样能跑，只是结果差几十倍。所以比较不同宿主之前，要先确认大家用的是同一种单位。

## 深入一点：方程与换算细节

**示踪物方程。** 对任何一个溶解或悬浮在水里的生物量 $c_i$（比如硅藻碳），物理模型要解：

$$
\frac{\partial c_i}{\partial t} = \underbrace{\frac{\partial}{\partial z}\left(\nu'_t \frac{\partial c_i}{\partial z}\right)}_{\text{湍流混合（物理模型）}} - \underbrace{\frac{\partial (w_i c_i)}{\partial z}}_{\text{沉降/上浮}} + \underbrace{\sum_{m} S_i^{(m)}(\mathbf{c}, T, I, \dots)}_{\text{所有模块的源汇（FABM）}}
$$

其中 $t$ 是时间，$z$ 是深度坐标（向上为正）；$\nu'_t$ 是湍流扩散率，表示湍流把物质上下混匀的能力；$w_i$ 是沉降速度（向下沉为负，上浮为正），由模块告诉 FABM；$S_i^{(m)}$ 是第 $m$ 个模块对 $c_i$ 造成的变化率，它可能依赖所有生物量 $\mathbf{c}$、水温 $T$、光照 $I$ 等。求和号表示把所有模块的贡献加起来。GOTM 对沉降默认用带限制器的三阶迎风格式（一种不产生虚假振荡的数值方法）。

**时间积分方法。** 源汇项怎样往前推，可以在 `gotm.yaml` 的 `fabm` 段选择：前向欧拉（按当前速率直接往前推一步）、二阶或四阶龙格–库塔（在一步里多试算几次，更准），或者保证浓度不会算成负数的 Patankar 类格式，还可以设置子步数（把一步拆成几小步）。

**深度积分的鱼。** E2E 的鱼假设能利用整根水柱的食物。鱼模块借助 FABM 内置的“垂直积分”子模块，先算出猎物在整根水柱里的总量

$$
P_X = \int_{\text{bottom}}^{\text{surface}} C_X\, dz
$$

其中 $C_X$ 是猎物 $X$ 在各层的浓度（mg C m⁻³），积分从海底到海面，得到每平方米海面下的总量 $P_X$（mg C m⁻²）。鱼用 $P_X$ 算一共吃多少，再按每层猎物所占比例 $C_X/P_X$ 把摄食分回各层。MIZER 也是按深度积分的模型，同样按猎物的垂直分布把捕食分回各层（见[粒径谱一章](chapter:06-size-spectrum)）。

**守恒的一般形式。** 对任何守恒元素：

$$
\frac{d}{dt}\left(\sum_{\text{所有库}} c_j\right) = \text{边界通量}
$$

左边是系统里这种元素所有“库”（营养盐、浮游生物、鱼、碎屑、沉积物……）的总量变化率，右边只剩跨越系统边界的流动：海气交换、沉积物埋藏、向气候态的松弛（每一步把模型值往观测平均剖面拉一点）等。模块可以把自己的变量登记进“总碳”“总氮”“总磷”等聚合量，方便检查。ERSEM 和 FABM-MIZER 都这样做；官方 E2E 代码没有登记，检查时要把鱼和大型底栖动物的碳按 1/12.01 换成 mmol，再按 Redfield 比算出氮、磷，自己加进去。

**换算系数的来历。**

- ERSEM 的铵盐和磷酸盐：C:N $=106:16=6.625$（摩尔比），所以 $1\ \mathrm{mmol\,N}$ 相当于 $6.625\times12.01\approx79.6\ \mathrm{mg\,C}$（12.01 是碳的摩尔质量，g/mol），`scalenh4` $=79.57$；$1\ \mathrm{mmol\,P}$ 相当于 $106\times12.01\approx1273\ \mathrm{mg\,C}$，`scalepho` $=1273$。
- ERSEM 的 DIC（修正版用到）：$1\ \mathrm{mmol\,C} = 12.01\ \mathrm{mg\,C}$，`scaledic` $=12.01$。
- ECOSMO：营养盐本来就折算成碳，不需要换算。
- ERGOM：浮游生物、碎屑以 mmol N 计，`scaleprey`、`scaledet` 等取 79.6；营养盐以 mmol N、mmol P 计，`scalenh4` $=79.57$、`scalepho` $=1273$。

再举一个例子：如果某个宿主的碎屑以 mol C kg⁻¹（每千克海水多少摩尔碳）计，而 E2E 要的是 mg C m⁻³，乘子约为

$$
1\ \mathrm{mol\,C\,kg^{-1}} \times 12011\ \mathrm{mg\,mol^{-1}} \times 1025\ \mathrm{kg\,m^{-3}} \approx 1.23\times10^{7}\ \mathrm{mg\,C\,m^{-3}}
$$

其中 12011 是每摩尔碳的毫克数，1025 是每立方米海水的近似质量（千克）。

**固定元素比例的浮游动物。** 官方代码从猎物里扣氮、扣磷都按 Redfield 比例（鱼体只记碳，氮磷按固定比例隐含），不按猎物实际的氮碳比。

> **想一想**：ERSEM 的中型浮游动物 Z4 只有一个碳变量，为什么也能参与氮、磷的守恒？
>
> 答：ERSEM 假定 Z4 体内元素比例固定：每 mg 碳带 0.0126 mmol 氮、0.000786 mmol 磷。换成摩尔比，C:N $= (1/12.011)/0.0126 \approx 6.6$，C:P $\approx 106$，正好是 Redfield 比。鱼吃掉 Z4 的碳时，氮和磷按这两个比例一起算。

## 容易误解的地方

- **FABM 不是生态模型。** 它自己没有任何生物方程，只负责登记、接线和传递速率。只说“用 FABM 跑的结果”是不完整的，要说清用了哪些模块。
- **FABM 按名字接线，但不管生态上合不合理。** 你完全可以让鱼去“吃”硝酸盐，FABM 不会报错。食性是否合理，要使用者自己把关。
- **单位错了也不会报错。** 换算系数写错，模型照样能跑，结果却差几十倍。
- **FABM 里也能做“单向耦合”。** 单向耦合指鱼读取浮游生物来生长，但吃掉的不从浮游生物里扣。一种做法是先单独跑浮游生物模型、存下结果，再用存下的结果驱动鱼（方法参考：Powley 等 2026）。软件用一个思路相同、更省事的办法：FABM-MIZER 模块有个 `feedback` 参数（默认开启），关掉后鱼照常读取猎物，但不把捕食、排泄、呼吸等写回宿主。软件里的“单向耦合”配置就是 `feedback: false`（见[单向与双向耦合一章](chapter:08-coupling)）。
- **“宿主”在不同文档里指不同的东西。** FABM 文档里的 host 是物理模型；本软件里的宿主是低营养级生态模型。
- **改 `fabm.yaml` 不用重新编译，改模块源码才要。** 在网页上调参数属于前一种。
