# 认识 Shoal：它是什么，第一个项目怎么做

> **一句话**：Shoal 是一个在自己电脑上模拟浅海生态系统的工具，从营养盐、浮游生物一直算到鱼，用对照实验回答“如果改变某个环节，海里会怎样”。

**这一章你会明白**

- Shoal 模拟的是什么，适合回答哪类问题，不适合回答哪类问题；
- 几个贯穿全书的基本词：水柱、低营养级、高营养级、宿主、对照实验、预热；
- 界面上每一页是做什么的；
- 怎样从零开始做第一个项目，并看懂第一批结果；
- 读完这一章接下来该读哪里。

## Shoal 是什么

想象在海上某一点，从海面到海底插下一根很长的“试管”。管子里的海水会被太阳晒暖、被风搅动、在冬天变冷下沉。水里漂着营养盐和浮游植物（单细胞的微小藻类），浮游植物被浮游动物（桡足类这样的小型动物）吃掉，浮游动物又被鱼吃掉，死掉的生物沉到海底，被细菌和贝类、蠕虫分解，营养盐又回到水里。

Shoal 用计算机把这根“试管”里一年又一年发生的事算出来。它面向**陆架海**，也就是大陆边缘水深一般不到 200 m 的浅海，例如北海、东海、黄海、波罗的海。全世界任何一片陆架海都可以选作研究点。

这种从营养盐一路算到鱼的模型叫**端到端模型**（end-to-end，常写作 E2E）：食物链的两端都在模型里。它的价值在于，食物链上任何一环变了，影响可以沿着链条上下传递，而不是被切断。为什么这很重要，见[为什么要把鱼和浮游生物放进同一个模型](chapter:01-why-e2e)。

## 它能回答哪些问题

Shoal 把研究组织成“问题”。新建项目时，你勾选想研究的问题，软件就生成一组对照实验。目前有五类：

| 想知道 | 界面上的实验设计 | 怎么回答 |
|---|---|---|
| 这个海区一年里水温、营养盐、浮游生物怎么变？ | 单个低营养级模型 | 只算浮游生物这一层，看季节变化 |
| 鱼和海底动物会把浮游生物压低多少？ | 高营养级的下行控制 | 分别加入、去掉鱼和海底动物，比较差别 |
| 换一个浮游生物模型，上面的结论还成立吗？ | 宿主模型对比 | 同一套鱼接到不同的浮游生物模型上 |
| 鱼吃掉的东西要不要从浮游生物里扣掉？ | 耦合方式：单向 vs 双向 | 比较“鱼不影响食物”和“鱼真的吃掉食物” |
| 用不同方式描述鱼，结论会不同吗？ | 高营养级表示方式：功能群 vs 粒径谱 | 按食性分组的鱼和按个头分档的鱼并排比较 |

每一类问题背后的道理和读结果的方法，见[对照实验一章](chapter:13-designs)。

它**不适合**回答的问题也要说清楚：

- 某一种鱼（比如鳕鱼）明年会有多少。模型里的鱼是“一类吃浮游动物的鱼”或“某个体重档的鱼”，不是具体物种。
- 渔业配额、捕捞管理方案。
- 海流怎样把污染物或鱼卵从一处带到另一处。每根水柱只算上下方向，不算水平海流。

## 先认识几个词

后面每一章都会用到这些词。这里先给一个直观的说法，详细解释在对应章节。

- **水柱**：海上某一点从海面到海底的一竖条海水。Shoal 的基本计算单元就是一根水柱，只算上下方向的变化，所以也叫一维模型。见[水柱物理一章](chapter:02-water-column)。
- **低营养级**：食物链的下半段，包括营养盐、浮游植物、浮游动物、细菌和碎屑（死掉的有机颗粒）。见[浮游生物一章](chapter:04-lower-trophic)。
- **高营养级**：食物链的上半段，这里指鱼和大型底栖动物（贝类、多毛类等住在海底、肉眼可见的动物）。
- **宿主**：负责低营养级的那部分生态模型。鱼的模块接在它上面取食，就像电器插在插座上。Shoal 提供三个宿主：ERSEM、ECOSMO、ERGOM。见[三个宿主一章](chapter:05-hosts)。
- **功能群**和**粒径谱**：描述鱼的两种办法。功能群按“吃什么、住哪里”分组；粒径谱不分物种，只按个头分档。见[功能群一章](chapter:07-functional-groups)和[粒径谱一章](chapter:06-size-spectrum)。
- **对照实验**：只改一个条件、其余完全相同的几次模拟。就像两盆一样的花放在同一个窗台，只给一盆施肥，长得不一样就只能怪肥料。
- **预热**：模型开始时的状态是人为给的，要先空跑几年，等每年的季节变化基本重复了（叫进入**稳态**），后面的年份才拿来分析。就像新鱼缸要先“养水”几周才能放鱼。

## 屏幕上有什么

左侧是导航栏，从上到下的顺序就是做事的顺序：

| 页面 | 这一页回答什么 | 你在这里做什么 |
|---|---|---|
| [项目](app:home) | 我在研究什么？做到哪一步了？ | 新建或打开项目；页面上的“研究流程”会提示下一步 |
| [站点与物理](app:site) | 研究点在哪里？那里的天气和海水是什么样？ | 查看或修改经纬度、水深、气象年份；看气象和观测剖面图；设置模拟年数、层数、潮流强弱 |
| [食物网配置](app:foodweb) | 模型里有哪些生物、谁吃谁？ | 选择宿主和鱼的模块，开关鱼和底栖动物，修改参数；页面上的食物网图就是实际运行用的接线 |
| [实验与运行](app:experiments) | 要比较哪几次模拟？ | 一键运行一组对照实验，看进度和日志 |
| [结果分析](app:results) | 结果是什么？几次模拟差在哪里？ | 指标对比表、时间–深度图、年循环、差值、粒径谱、食物网状态、验证与稳态检查 |
| [三维陆架](app:shelf) | 换到整片海区，格局怎样？ | 在一个经纬度框里每个格子放一根水柱，把结果画成地图（可选） |

左下角还有**入门教程**（就是本书）和**设置**。顶部菜单栏右侧有 **AI 助手**（Ctrl+Shift+A），它能读取你的项目和结果、检索本教程、帮你启动模拟；它提出的配置修改要你确认后才会生效。屏幕底部的**任务面板**（Ctrl+J）显示正在下载数据或运行的任务。

## 第一个项目：跟着做一遍

下面这个小项目回答一个具体问题：**在北海中部，鱼和海底动物会把浮游动物压低多少？能不能用“让浮游动物多死一点”来代替鱼？** 全程大约半小时到一小时，大部分时间是电脑在算。

### 第 1 步：新建项目

在[项目](app:home)页点“新建项目…”（或按 Ctrl+N）。对话框里依次填：

1. **研究海区**：在世界地图上点一个位置，或者直接点“北海中部”预设（56°N 3°E，水深 73 m）。这是一个夏季分层、冬季混合的典型温带陆架站点，参数资料也最全，适合入门。
2. **气象年份**：起止年份都填同一年（默认 2014）。软件会反复使用这一年的天气，直到模型稳定。
3. **要研究的问题**：勾选“高营养级的下行控制”。
4. **低营养级模型（宿主）**：第一次可以只选 ECOSMO。它算得快，鱼的模块最初也是在它上面开发的。

对话框底部会显示一共要跑几次。这里是 5 次：

| 配置 | 意思 |
|---|---|
| ECOSMO 仅低营养级 | 只有浮游生物，没有鱼和底栖动物，作为基准 |
| ECOSMO + 大型底栖 | 只加海底动物 |
| ECOSMO + 鱼类 | 只加两类鱼 |
| ECOSMO + 鱼类 + 底栖（完整） | 鱼和海底动物都加 |
| ECOSMO 浮游动物死亡率 +20% | 不加鱼，只让浮游动物多死 20%，看这样能不能“冒充”鱼 |

没有网络时，勾选“没有网络：使用离线算例”。站点会换成 GOTM 自带的北海北部算例（59.33°N 1.28°E，110 m，1998 年），不用下载任何数据，其余步骤相同。

### 第 2 步：等站点数据准备好

点“创建项目”后，软件在后台下载这个点的三类公开数据，约 1–3 分钟：

| 数据 | 内容 | 用途 |
|---|---|---|
| ERA5 | 逐小时的气温、风、云量、太阳辐射、降水等（欧洲中期天气预报中心的再分析，把各种观测和天气模型融合出的历史天气） | 驱动海面的加热、冷却和风搅动 |
| WOA23 | 世界海洋图集 2023 版的月平均温度、盐度、营养盐、氧的垂直分布（多年观测平均，叫气候态） | 模型的初始状态，也是模型被轻轻拉向的目标 |
| ETOPO 2022 | 全球海底地形 | 没有手填水深时，查出这个点的水深 |

数据缓存在本机，同一个站点第二次构建不用再下载。下载完成后打开[站点与物理](app:site)看看：气象图上冬天风大、夏天日照强；剖面图上夏天上暖下冷，冬天上下一样。这就是后面浮游生物季节变化的“舞台”。

### 第 3 步：运行实验

打开[实验与运行](app:experiments)，选中“下行控制 · ECOSMO”，点“全部运行”。5 次运行会排队计算，同时跑几个由设置里的“最大并行运行数”决定（默认 2）。默认是“快速设置”：预热 4 年，再分析 1 年。

### 第 4 步：看结果

全部完成后打开[结果分析](app:results)，在左侧勾选这 5 次运行。第一个勾选的运行是**基准**，其余都和它比。建议按这个顺序看：

1. **时间–深度图**：选温度，看夏季表层的暖水层怎样形成、秋冬怎样消失。再选浮游植物（硅藻、鞭毛藻），看春季藻类大量繁殖（水华）出现在什么时候、什么深度。横轴是时间，纵轴是深度，颜色是数值。
2. **指标对比**：表里列出每次运行的年平均值，以及相对基准的百分比变化。找到中型浮游动物这一行，比较“完整配置”和“+20%”各让它变化了多少。
3. **时间序列**：选中型浮游动物，看“完整配置”和“+20%”两条年循环曲线。如果两者只是高低不同、形状一样，说明多死 20% 确实能冒充鱼；如果高峰出现的时间也变了，说明鱼的作用不止“多死一点”。
4. **验证与稳态**：检查预热够不够。如果最后两年变化还很大，说明结果还带着初始值的影子，需要在站点与物理页把预热年数加多。

在北海中部的同类模拟里，显式加入鱼和底栖动物，对浮游动物的压制比“死亡率 +20%”更强，还改变了它一年中的起落节奏（Vijayakumaran 等 2026）。你的结果是否如此，可以自己判断。快速设置只预热 4 年，鱼和海底动物还没完全稳定，数字仅供熟悉流程。

### 第 5 步：往下走

- 再新建一个项目，勾选三个宿主和“宿主模型对比”，看结论是否换了模型还成立。
- 换一个你关心的海区，重复同样的实验。
- 正式研究时，把预热改成 10–20 年。

## 容易误解的地方

- **一根水柱不代表整片海。** 它代表“假如这一点是一根孤立的水柱”会怎样。海流、河流带来的物质只能用观测平均值近似。
- **模型里的鱼不是具体物种。** 结果说“鱼 1 增加 10%”，意思是“吃浮游动物的那一类鱼”增加，不是鲱鱼增加。
- **看差别比看绝对值可靠。** 对照实验里各次运行共有的误差会在差值中部分抵消，所以结论最好建立在“完整配置比基准少了多少”这类比较上。
- **离线算例只用于熟悉软件。** 它在北海北部、只有 1998 年一年的天气，不适合和文献数值比较。
- **改了站点会重新下载强迫数据。** 已有的运行结果保留，但之后的新运行用新数据。
- **删除项目不会马上永久删除。** 项目先移到 `workspace/trash/`，需要时可以找回。

## 安装与开发说明

**桌面版（大多数人用这个）**：在 macOS、Windows 或 Linux 上安装 Shoal 桌面版，双击打开即可。计算内核已经编译好并打包在安装程序里，不需要装 Python 或编译工具。打开后到[设置](app:settings)页看一眼“计算内核”是否就绪，也可以在这里填写 AI 助手的接口地址和密钥（兼容 OpenAI 接口的模型；不填也能用其他所有功能）。

项目数据保存在系统的应用数据目录：macOS 是 `~/Library/Application Support/Shoal`，Windows 是 `%LOCALAPPDATA%\Shoal`，Linux 是 `~/.local/share/shoal`。

**从源码运行（开发者）**：需要 Python 3.11 和 Node.js。在仓库根目录用 `python -m venv .venv` 建好虚拟环境并安装依赖，运行 `pnpm kernel` 编译计算内核，再运行 `pnpm dev`，用浏览器打开 `http://localhost:5173`。完整步骤见仓库的 README。

软件由三部分组成：

| 部分 | 做什么 |
|---|---|
| 计算内核 | GOTM（一维水柱物理模型）+ FABM（把生态模块接进物理模型的框架）+ 生态模块：三个宿主 ERSEM、ECOSMO、ERGOM，以及两种鱼类模块 ECOSMO E2E（功能群）和 FABM-MIZER（粒径谱） |
| 计算服务 | 下载和准备站点数据、生成配置文件、排队运行模型、读取结果 |
| 界面 | 你现在看到的这些页面 |

一个项目在磁盘上是一个文件夹：

```
projects/<项目id>/
    project.json      名称、站点、模拟时间、实验设计
    site/             站点强迫文件（气象、WOA 剖面、site.json）
    configs/          食物网配置（宿主 + 高营养级模块 + 参数修改）
    experiments/      实验：一组按顺序排好的运行
    runs/<运行id>/    gotm.yaml、fabm.yaml、result.nc、gotm.log
    shelf/            三维陆架的设置与结果
```

每次运行的 `gotm.yaml`（物理设置）、`fabm.yaml`（生态模块和接线）和 `result.nc`（NetCDF 格式的结果）都保存在 `runs/` 下，可以用其他工具直接打开。站点除了自动生成，还可以选 GOTM 官方算例，或导入一个现成的 GOTM 设置目录（必须含 `gotm.yaml`）。
