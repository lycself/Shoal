# 对官方 ECOSMO E2E 代码的修正补丁

`ecosmo-e2e-corrections.patch` 由 `kernel/build.py` 打到官方源码的一份副本上（`kernel/build/ecosmo-e2e-src`），
`kernel/src/ecosmo-e2e` 里的官方文件本身不会被改动。

补丁只新增 FABM 参数，全部默认关闭。关闭时走的是原来的代码路径：同一个 ERSEM 配置跑 3 年，
599 个输出变量与未打补丁的程序逐位相同。Shoal 里在"食物网 → 物质收支"选"修正版"时，生成的
fabm.yaml 会把这些参数都打开；手写配置时也可以逐个打开，用来分别看每一处的影响。

## 修正了什么

逐条对照官方源码（ECOSMO E2E v2.0，`ecosmofish.F90` 与 `ecosmomb.F90`，2025-03-26 版）：

| 参数 | 模块 | 原代码的行为 | 修正后 |
|---|---|---|---|
| `fix_dom` | 鱼 | 水体里鱼未同化的食物和死亡个体，只有 (1−frr) 进入碎屑，frr（默认 0.4）那部分没有放回任何变量。同一个文件里鱼吃底栖动物的部分、以及底栖动物模块，都把 frr 部分放进 DOM | frr 部分进入 DOM（按 Redfield 比例带上氮、磷） |
| `fix_oxygen` | 鱼 | 排泄（呼吸）时氧气**增加**，数量为每 mol 氮 1 mol O₂ | 氧气减少，每 mol 碳 1 mol O₂，缺氧时不再耗氧，与底栖动物模块相同 |
| `fix_silica` | 鱼、底栖 | 从饵料、碎屑扣硅，往碎屑、沉积物还硅，都按 Redfield 比例对**全部**碳通量计算。吃不含硅的浮游动物也会往碎屑里"还"硅，吃硅藻扣的硅和还的硅也对不上 | 鱼和底栖动物不保留硅：吃下的硅按饵料实际的硅碳比扣除，原样排到碎屑（鱼）或沉积物（底栖） |
| `fix_dic` | 鱼、底栖 | 排泄掉的碳不进入任何变量 | 进入宿主的溶解无机碳（ERSEM `O3/c`、ECOSMO `CO2/dic`）。ERGOM 没有碳酸盐系统，不适用 |
| `fix_boltzmann` | 底栖 | 排泄的温度项用 8.617×10⁻⁴ eV/K（鱼模块用的是正确的 8.617×10⁻⁵） | 改为 8.617×10⁻⁵。官方算例里 `tempcMB1 = 0`，所以默认参数下没有影响 |

`scaledic` 是宿主 DIC 单位到 mg C 的换算系数（ERSEM、ECOSMO 为 12.01）。

## 验证

1. **关闭时不变**：打补丁前后的程序跑同一个 3 年 ERSEM 配置，全部输出逐位相同。
2. **收支闭合**：宿主换成不发生任何反应的被动示踪物，只让鱼和底栖动物运行 240 天，统计碳、氮、磷、硅的总量（鱼和底栖动物按 Redfield 比例计入）：

   | | 碳 | 氮 | 磷 | 硅 | 氧 |
   |---|---|---|---|---|---|
   | 原代码 | −134 mmol m⁻² | −6.9 | −0.43 | −7.8 | −29 |
   | 修正版 | −0.001 | −0.0008 | +0.0001 | 0.0000 | −88（= DIC 增加的 88） |

   修正版的残差来自输出精度。

## 没有改的

- **氮、磷按 Redfield 比例扣除**：鱼和底栖动物只有碳一个状态变量，体内氮磷固定为 Redfield 比例，所以按 Redfield 比例从饵料扣氮磷是这一设计的自然结果，总量守恒。代价是饵料的实际氮碳比会被慢慢推离原值；饵料氮磷比低于 Redfield 时（例如降解过的碎屑）可能扣成负值。
- **半饱和常数的单位**：鱼的 `rF1`、`rF1MB` 乘 79.57 换成 mg C 后，和深度积分的饵料、碎屑、大型底栖动物（都是 mg C m⁻²）相加。分母各项单位一致，所以公式没有错，错的是标注：代码注释写 mmolN/m³、论文表写 mmol C m⁻³，实际是 mmol N m⁻²。界面按 mmol N m⁻² 标注，计算不改。大型底栖动物的 `rMB1` 与底层浓度（mg C m⁻³）和沉积物碎屑（mg C m⁻²）相加，隐含取食海底以上 1 m 的水层；这是假设而非错误，也不改。
- **鱼 2 摄食率**：ERSEM 算例文件写 0.004 d⁻¹，发布的参考结果与 0.0045 吻合。Shoal 沿用算例文件的值。
